# 统一改造实施摘要

## 数据链

- 真实企业源位于 `runtime_data/enterprise_source`，共 117 家；
- 运行画像位于 `runtime_data/enterprise_profiles`；
- 项目只通过远程 MySQL 读取；
- 模型只保留正式智谱 Provider；
- 核心依赖失败时禁止启动和业务回退。

## 企业画像

- 原始企业 JSON 只读；
- 用户补充和派生结果独立写入；
- 企业评价后端规则、权重、总分和等级保持冻结；
- 发布验证使用 SHA-256 清单检查核心规则文件；
- V3 将企业评价前端恢复为原有分区式工作台结构，不恢复 Mock、Fixture、Replay、演示审核或测试数据重置入口。

## 投标决策

- 真实项目后端分页，取消 60 条上限；
- `bid_open_time` 仅按开标时间展示，不作为截止过滤或评分依据；
- 支持跨页单选/多选和组合比较；
- 团队槽位和关键人员冲突执行硬约束；
- 资格严格保持 `PASS/FAIL/UNKNOWN`；
- `TEMP-BID-SCORE-V2` 为资格40 + 能力40 + 资源20；
- 本次偏好独立影响 AI 分析、最终优先级和组合，不计入客观基础分。

## V3 投标决策前端修复

- 业务结果不再显示 `db-project-*`、内部排名字段或英文内部枚举；
- 最终决策使用真实项目名称的结构化卡片；
- AI 说明、资源冲突和行动建议经过展示层清洗；
- 主按钮、次按钮、危险按钮和禁用按钮使用高对比度样式；
- 竞争分析只通过独立路由打开新标签页；
- 删除投标决策页内向下滚动显示竞争分析的旧交互。

## 竞争分析

- 当前关系数据不可用时，默认使用独立的 3 条演示竞争者；
- 页面、接口、持久化结果均携带 `data_is_demo` 和警告；
- 演示数据不写入远程数据库，也不参与决策评分；
- 独立详情页明确显示我方企业、目标项目、数据状态、覆盖率和行动建议。

## 启动与安全

- Windows 专用，根目录只保留 `start.ps1`；
- 启动前真实检查企业 JSON、远程数据库和智谱 GLM；
- 四个服务仅监听 `127.0.0.1`；
- 不建设登录系统，审计操作者为 `LOCAL_OPERATOR`；
- `.env.local` 不进入交付 ZIP，只保留空值 `.env.example`。
