# 投标决策现场问题修复验收报告

日期：2026-07-31  
目标平台：Windows 10/11  
评分版本：`TEMP-BID-SCORE-V2`

## 1. 本轮修复范围

本轮只修复现场测试确认的投标决策问题，不修改企业画像评价规则、权重、总分或等级。

### 1.1 阻断性证据校验

- 为每条竞争对手演示数据登记与结果引用一致的 `demo:competition:N` 证据 ID；
- 接受待核验条件后可继续进入竞争分析；
- 拒绝项目后不再对该项目执行竞争分析；
- 恢复任务失败时，将任务状态置为 `NEEDS_HUMAN_REVIEW`，同时清除旧确认按钮，防止在部分推进的检查点上重复提交。

### 1.2 资格缺口补充

- 资格缺口按项目、按资格要求分别展示；
- 显示项目名称、要求原文、要求类别、UNKNOWN 原因、所需材料；
- 补充键采用 `project_id::requirement_id`，只绑定一个项目的一条要求；
- 补充材料不再进入审核流程，只绑定对应项目与资格项并立即重新核验；
- 未结构化资格要求不显示无意义输入框，只允许保持 UNKNOWN 继续分析或结束分析。

### 1.3 本次目标与偏好

- 智谱 GLM 解析行业、地区、预算、风险偏好、明确排除条件和优先因素；
- 前端展示解析后的本次偏好；
- 偏好影响 AI 分析、最终排序和多项目组合；
- 偏好不改变资格三态，也不计入客观 100 分；
- 明确排除条件命中的项目不能进入本次组合。

### 1.4 临时评分 V2

客观基础分固定为 100 分：

| 维度 | 分值 |
|---|---:|
| 资格可投性 | 40 |
| 企业能力匹配 | 40 |
| 资源可执行性 | 20 |

企业能力子项：行业 15、技术与同类业绩 15、地区 5、项目规模 5。  
资源子项：团队槽位 10、关键人员与证书 10。

前端默认展开并展示：

- 完整统一评分规则；
- 硬约束与优先级规则；
- 每个项目各维度和子项的实际得分；
- 本项目判断、得分原因、使用数据、缺失数据；
- 与客观分分离的本次偏好匹配结果。

以下内容不参与客观基础分：

- `bid_open_time` 与准备时间；
- 合同风险；
- 演示竞争对手；
- 中标概率；
- 旧推荐分；
- 用户本次偏好。

### 1.5 时间字段语义

- 删除 `bid_open_time → bid_deadline` 的直接映射；
- 前端显示为“开标时间（数据库 bid_open_time）”；
- 不用于过期过滤、项目关闭判断、准备时间评分或结果有效期；
- 当前项目列表只按权威状态 `TENDER / PLAN` 查询；
- 未取得语义明确的真实投标截止字段前，不恢复截止时间计算。

## 3. 当前环境限制

本次 Linux 验证环境缺少 Rollup 的 Linux 可选原生包，因此 Vite 最终打包未在此容器完成；Vue TypeScript 检查已通过。交付包不包含 `node_modules`，Windows 使用 `npm ci` 安装对应平台依赖后执行构建。

当前容器也不具备用户本机的 `.env.local`、SSH 隧道、远程数据库凭据和智谱密钥，因此不声称本轮新包已完成 Windows 真实联调。启动脚本仍会在 Windows 启动前真实检查企业数据、远程数据库和智谱 GLM。

## 4. Windows 复测要求

1. 停止旧项目，但 SSH 隧道可保持；
2. 解压本轮新 ZIP 到新目录；
3. 将旧目录的 `.env.local` 复制到新目录，不要发送配置内容；
4. 使用 uv 创建 `.venv` 并安装 `requirements-lock.txt`；
5. 执行两个 `npm ci`；
6. 运行 `start.ps1`；
7. 必须重新创建新投标决策任务，不恢复此前已报错的旧任务；
8. 重点复测接受待核验、结束分析、偏好解析、完整评分规则和逐项资格缺口。
