# 当前系统架构

## 服务组成

| 服务 | 地址 | 职责 |
|---|---|---|
| Vue Web | `127.0.0.1:5173` | 企业、项目、决策、竞争分析和统一错误页 |
| Node 薄网关 | `127.0.0.1:3000` | 前端统一 API、就绪检查、请求转发 |
| 企业画像服务 | `127.0.0.1:8000` | 企业事实/能力/评价与补充 |
| 投标决策服务 | `127.0.0.1:8001` | 项目查询、资格、评分、多项目组合、竞争分析 |

全部服务仅监听本机回环地址。

## 启动顺序

```text
start.ps1
→ 读取 .env.local
→ 校验工具和端口
→ 安装锁定依赖
→ preflight.py
   ├─ 真实企业 JSON 检查
   ├─ 远程数据库只读检查
   ├─ 真实有效项目读取检查
   └─ 智谱 GLM 真实最小调用
→ 全部通过后启动四个服务
→ 逐个健康检查
→ 打开 Web
```

任何核心检查失败，所有已启动子进程都会被清理，页面只展示统一错误信息。

## 决策链

```text
选择我方真实企业
→ 后端分页读取真实有效项目
→ 选择一个或多个项目
→ 逐项资格 PASS/FAIL/UNKNOWN
→ TEMP-BID-SCORE-V2 分项评分
→ 检查团队槽位和关键人员冲突
→ 生成单项目结论和多项目组合
→ 调用智谱 GLM 生成受事实约束的解释
→ 持久化决策、轨迹和审计
```

资格 `FAIL`、项目过期、资源硬冲突等确定性规则不能被 GLM 覆盖。

## 竞争分析边界

当前远程 `project_company_relation` 表没有可用业务记录，因此默认使用独立的演示竞争者文件，仅验证界面和流程。页面、接口和持久化结果必须携带演示标志和警告。数据库查询错误必须明确失败，不能伪装成零条记录。
